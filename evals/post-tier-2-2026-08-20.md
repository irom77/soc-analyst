### `ip-verdict-claim` — do not read this as an improvement

This case moved from a 2:1 split in both prior runs to unanimous `Insufficient Data`
with `Low` confidence ×3. It is tempting to attribute that to the citation
requirement from `fa315a7`, which forces every finding to name `source_paths` and so
makes "the evidence is not here" the path of least resistance on a case whose whole
point is an unsupported recorded verdict.

**Three samples cannot support that claim.** If the underlying rate is the 2/3 the
prior runs suggest, a 3-for-3 result occurs about 30% of the time by chance. This is
comfortably inside noise. The confidence column does not add independent evidence
either: `High` was attached to the `False Positive` samples in the prior runs, so
confidence is tracking the verdict rather than moving on its own.

What can be said: the two verdicts involved are *both* in the case's allowed set, this
was already the least stable case in the benchmark, and nothing moved in a bad
direction. Establishing a real shift would need a sample count this harness has not
been run at.

## New fields, confirmed on live output

Items 1, 2, and 4 had been verified only against a stubbed analyze function. This run
is the first live confirmation:

- **Provenance** (`case_analyzer_run`) is present in all 18 saved reports, with
  `model`, `endpoint_host` (host only — no credentials from the base URL),
  `package_version`, `input_file_sha256`, `payload_sha256`, `system_prompt_sha256`,
  `report_schema_version`, and the `has_*` flags populated.
- **Citations**: `evidence_findings` entries carry `source_paths` pointing into the
  case export, and `checks.problems` is empty in all 18 — the deterministic
  post-check found no unresolvable path.
- **Truncation**: `truncated_fields` is present and empty on every report, which is
  the correct answer for these small cases rather than an unexercised field.
- **Enums**: every verdict and confidence value falls inside the constrained
  vocabulary; no request was rejected for an out-of-vocabulary value.

## What this run does not establish

As with the earlier runs, a PASS means the verdict fell inside the allowed set, not
that every claim in the report is correct. Six cases at three samples is a tripwire,
not a quality measurement — it is sized to catch a change that breaks behaviour
outright, and it did not catch one. It has no power to detect a small degradation,
and `ip-verdict-claim` is a live demonstration that it cannot resolve differences of
one or two samples.

The enrichment work in Tiers 1 and 2 (items 5, 6, and 7 — response cache, provider
pacing, UTS #46 encoding, URLhaus and email observables) is **not exercised by this
harness at all**: it never contacts enrichment providers. Those remain verified
offline only, against fakes. A live enrichment run is a separate check.
